# 增量更新本地验收

实施分支为 `feat/incremental-update`。本次只修改本地 APP、Rust API 与私库 Go 工具；未推送、部署、上传生产对象或发版，已发布的 1.1.0 原 APK 保持原字节。

## 实现

- `update-core` 固定 HDiffPatch 5.1.3／Zstd 1.5.7，提供流式断点下载、签名说明认证、真实 PM 基线检查、隔离进程 FD 合并、完整 APK 验证及持久化恢复。错误签名不回退；取消保留断点；不适用或坏补丁使用同一签名目标的完整包。
- 业务通过 `SharedUpdate` 调用宿主；恢复任务重新验签后显示“继续下载”，用户操作后才下载。演奏开始时暂停正在运行的普通更新，网络与 Binder 取消收尾在后台完成。旧接口完整包下载保留；它的业务 I/O 租约也会暂停热更准备。
- 普通更新与热更分别使用事务、暂存目录和清理锁。热更重建进入原对象库，继续经过既有激活、健康确认与回退；固定当前宿主版本和 SDK 身份。
- Go `lxupdate` 准备最近三个正式基线直接到目标的补丁，重新构建并检查原字节及证书。只有至少节省 30% 且 64 KiB 的补丁进入说明。发布流程在全包和补丁完整回读后生成清单；增量准备与服务端灰度默认关闭。
- 新 SDK 输出参与宿主配置指纹生成，内置恢复组合随构建生成，不沿用 1.1.0 的 SDK 指纹。

## 实际 APK 与系统安装

使用临时 P-256 根／内容授权、本机 HTTP 服务及 Debug 签名。测试密钥和 APK 位于工作区忽略的 `tmp`；不使用生产私钥。A 为 code 18，B 为 19，C 为 20。

| 输入 | 原 APK 字节数 | C 字节数 | 实际补丁字节数 |
| --- | ---: | ---: | ---: |
| A | 46,106,619 | 35,480,085 | 728,340 |
| B | 35,262,365 | 35,480,085 | 704,930 |

此 C 验收产物 SHA-256 为 `2c24e6ff3489dc6fbc4b13e503b453a7531e5a18f74f79eea4113c62512e0d4c`，SDK 指纹为 `2ced9859f336d57b1d40d09e7b1ef25afc3085536d3aed077aee179f75b1c46e`。这些是本地验收标识，不是正式发布包、生产授权或未来节省比例。

API 36 上 A→C 和 B→C 均真实调用宿主桥、认证说明、校验当前 PM 基线、隔离合并、验证 APK，并通过安装分享入口读取完整文件。设备导出的结果与 C 摘要完全一致；执行真实系统覆盖安装后，生产曲库重新读取同一非空曲谱，曲目、解析事件、选曲和曲库设置保持。生产导入器生成的非空外部壁纸项目在演练场显示首帧，原选择和文件保持；无障碍组件启用记录仍然保留。

API 26 上也执行了 A→C 的真实宿主桥与完整验证流程，实收补丁 728,340 字节。测试服务故意以 64 字节／毫秒发送补丁以制造取消和续传窗口，所以约 17～20 秒的整轮耗时不代表正式下载速度。

## 失败和恢复

- 篡改说明、错误安装证书：在任何下载前拒绝，已有有效缓存也不能绕过签名。
- 错误基线：实际转完整包，下载 35,480,085 字节，最终 APK 验证成功。
- 损坏补丁：先收到 728,340 字节坏补丁，再转完整包；实际累计 36,208,425 字节，当前安装不变。
- 下载取消：中止本轮，不触发整包回退，保留已认证任务。强制停止进程、重新启动 APP 后，真实界面出现“上次更新／继续下载”；随后以 Range 恢复并准确重建。
- 测试镜像继承的 HTTP 代理曾截断完整包尾部；大小与 SHA 检查拒绝该内容，未进入安装。只关闭自建测试模拟器的代理后完整包路径通过，未修改电脑代理或真实手机设置。
- 已见根授权下限：即使授权文件缺失，普通更新仍读取激活日志下限并拒绝旧授权，活动热更选择不变。
- 原生测试在 API 26／29／36 覆盖精确输出、截断、可写基线 FD、同 inode 输出、运行中取消、SIGKILL 工作进程和新工作进程恢复。最后补充 Java 合并入口把旧文件本身／硬链接当输出的检查，API 26／36 均拒绝且基线不变。生产入口不再在原生 FD 验证前截断输出。

## 资源测量与构建

2,250,015 字节功能夹具的最终设备测量：

| API | 合并 RPC＋fsync | 合并前 VmHWM | 完成后 VmHWM |
| --- | ---: | ---: | ---: |
| 26 | 39 ms | 59,424 KiB | 62,592 KiB |
| 36 | 37 ms | 102,948 KiB | 108,092 KiB |

VmHWM 是该工作进程启动以来累计的 OS 峰值 RSS，包含 Android 运行时，未重置；这里不是纯解码器内存，也不是正式 APK 的峰值。解码器单独限制工作分配 32 MiB。

四 ABI 编译和 16 KiB ELF LOAD 对齐检查通过。原生库原字节合计 1,165,580，测试 APK 中未压缩存储；不包含 ZIP 对齐、Java／DEX／SDK 的新增体积。正式首包整体增量仍需同等构建配置的发版候选测量。正式历史 APK 的工具端对照另见私库验收记录，约 48.06% 下载节省，不能用功能夹具的比例代替。

最终 Debug JVM 检查：APP 115（2 个可选夹具跳过），hot-core 175（3 个可选设备／资源夹具跳过），update-core 14（Windows 符号链接权限跳过 1，WSL 已补测），buildSrc 20；失败均为 0。Go test／vet／离线 race、跨平台 CLI 构建、55 项发布脚本测试及 actionlint 已通过。

## 上线前剩余验收

ARM 真机、真实磁盘空间耗尽、正式签名发版候选整体体积和实际 APK 的 Android 峰值 RSS 尚未覆盖，不据此承诺所有设备或网络表现。线上迁移、更新专用委托签名配置、CI 固定工具提交和安装标识灰度开关需要部署前配置；本次没有启用。

首个支持增量的正式版本仍须完整升级一次，之后才可增量；网页和旧客户端保留全包。系统安装后的应用故障通过更高版本修复，热更继续走原自动回退。
