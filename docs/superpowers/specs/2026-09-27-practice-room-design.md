# 落弦律演练场设计

状态：用户已确认功能与交互设计；本轮交付实施文档和 HTML 开场预览，不实施 Android 页面。

## 目标与边界

主导航增加完整「演练场」，让用户手动弹奏本地口琴，或通过现有悬浮窗的截图识别、手势点击链路演练曲目。按键布局以用户提供的纯色背景口琴截图为准。这里不增加直接读取曲谱并自行播放的第二套播放器，不增加录音、评分或教程。

## 用户已确认的体验

1. 主导航入口，与曲库、发现等并列。演练场普通页面遵循 App 的浅色/深色主题、圆角卡片和蓝色主按钮。
2. 用户点击「进入演奏」后锁定横屏。等方向和布局稳定后开始约 1 秒的实时开场动画。
3. 开场采用「舞台开场」：背景渐暗 → 圆形边框依次描出 → 数字与文字显现 → 当前调式点亮。动画驱动实际按钮，不播放预录视频。
4. 入场音效由用户后续提供游戏“拿出口琴”的声音。当前明确保持静音，只保留可替换的接入点；不生成或寻找替代音效。
5. 演奏画面使用纯色深背景。下排八个音符按钮，上排半音、升调、自然音、降调四个按钮。保留参考图的圆形、相对坐标、间距、边框和高低音点。装饰不侵入按键识别区域。
6. 按住音符发声，松开短淡出。采用单音、后按优先；后按的新键接管声音，旧触点抬起不应误停新音，松开当前键后不自动恢复旧键。
7. 调式互斥，半音独立开关。模式切换影响后续按下的音符，不在一个仍被按住的音符中途重新触发音头。画面状态立即更新。
8. 自动演奏仅使用现有悬浮窗。每次实际触摸进入同一按键状态机，产生高亮和发声。
9. 离开演奏页面、应用切后台、触摸取消、音频焦点丢失时停止发声；退出恢复进入前的方向策略和系统栏设置。

## 页面与状态

建议主导航顺序：我的、曲库、发现、演练场、设置。同步修改 Pager、底部导航及首页侧栏，不保留写死的四页数量。

状态为 `Lobby → Orienting → Entering → Playing → Leaving → Lobby`。等待横屏不计入动画时长；只有进入 Playing 才接受音符触摸。返回键和退出按钮共用退出流程。系统限制方向切换时使用实际可用区域等比布局，不无限等待；竖屏或小窗空间不足时留在普通页面并给出说明。

演奏阶段隐藏 App 主导航和常规页面卡片，提供避开琴键区域的退出入口。保持屏幕常亮，退出时恢复。手动弹奏不依赖无障碍权限；使用悬浮窗时沿用现有授权流程。

## 几何与动画

使用一个参考坐标系同时生成按钮绘制位置和触摸区域，整体等比缩放，禁止 X/Y 分别拉伸圆形。参考图可归一化为 2048×512：音符圆心约为 X=[96,347,598,848,1098,1349,1600,1852]、Y=355、半径=86；调式圆心约为 X=[588,882,1116,1350]、Y=126、半径=74。最终以预览和参考图的视觉核对为准。

动画建议总长约 1.05 秒：

| 时间 | 表现 |
| --- | --- |
| 0–220ms | 普通页面淡出，背景收暗 |
| 120–750ms | 圆环按轻微错峰顺序描出，亮描边收敛成稳定细边框 |
| 430–820ms | 数字与调式文字淡入，最多数像素的轻微位移 |
| 800–1050ms | 自然音圆盘柔和点亮，转入可交互状态 |

首次进入默认自然音、半音关闭。退出重入重新初始化，避免遗留无声/升调状态。动画关闭或系统减少动态效果时，使用短淡入而不延迟演奏。中途退出须取消全部动画与回调；重入不能叠加旧的动画。

## 音源与发声

音源为现有 `assets/audio/samples/harmonica/Harmonica_*.wav`。已经核实共 39 个文件、48kHz/单声道/16-bit、每段约 11.5 秒。遵循 `tools/midi-renderer/render.py` 的实际音高和文件名映射：文件标签比实际音高高一个八度，不能按文件名直接当标准 MIDI 八度。

按键自然音间隔采用核心的 [0,2,4,5,7,9,11,12]；自然音基准 MIDI 60，升/降调分别 +12/-12，半音 +1。需要覆盖 MIDI 48–85，核对最高升调+半音对应 `Harmonica_Cs7.wav`，不能仅依脚本旧的 SAMPLE_MAX 常量截断。

采样去除起始静音并保留音头；普通音直接播放原采样，超出有效采样长度才循环稳定发声段。为每个样本离线选取、校验循环区间，交叉淡化避免重复音头、点击声和周期突变。松开时短淡出。Android 音频引擎自行消费样本，不在手机上运行 Python。

初次进入前预备音源，未就绪时不接受演奏；加载失败保留可重试的普通页面。资源、音频焦点和输出线程随生命周期释放。开场音效占位与口琴发声资源分开。

## 模块边界

- `PracticeScreen`：符合 App 风格的入口页。
- `PracticeStage` / `PracticeKeyboard`：方向、系统栏、动画、同源几何绘制与触摸。
- `PracticeSession`：纯逻辑的调式、半音、当前触点、单音规则和音高映射。
- `HarmonicaSampler`：样本准备、持续发声、淡出、音频焦点与资源释放。
- 已有 `MusicAccessibilityService`：继续负责选曲、截图识别和模拟点击。演练场通过真实触摸接收其操作，不读取服务内部时间线伪造播放。

## 验收

- 五个导航入口一致；演奏退出回到演练场普通页，不破坏其他页状态。
- 横屏稳定后动画才开始；退出恢复方向；连点进入/退出、动画中返回、切后台无残留音或延迟回调。
- 纯色背景布局视觉接近参考图，各屏幕上圆形不拉伸，触摸中心和显示中心一致。
- 所有模式与半音组合的映射正确；短按、长按超过 12 秒、多键交错抬起不串音、不挂音。
- 悬浮窗在演练场截图定位成功；实际点击触发高亮和音色，暂停后无遗留长音。
- Android 完成单元测试、Debug 构建及实机长音/焦点/转屏验证。HTML 只验证开场的节奏与视觉，不能代替 Android 验证。

## 本轮 HTML 预览

独立、无外部依赖的 HTML，展示入口、舞台开场、稳定琴键布局。支持正常速度、慢速观察、重播、退出和按键视觉交互。所有声音暂不接入，页面明确说明。浏览器内以横屏舞台展示，不声称实现 Android 自动转屏、无障碍点击或音频引擎。
