# 演练场实施计划

依据：[已确认设计](../specs/2026-09-27-practice-room-design.md)。2026-09-27：用户已认可开场预览，并授权按真实游戏比例校准后接入 Android。追加要求：半音与调式在按下瞬间切换，# 与高低音点对齐游戏。

## 1. 本轮：可评审开场预览

- 新建 `docs/previews/practice-opening/index.html`，所有 CSS、SVG 和脚本内联，离线可打开，不加载外部字体、CDN 或音源。
- 入口页使用现有品牌蓝与浅蓝灰背景；演奏舞台采用参考图的深色纯底和 12 个圆形按钮。
- 实现真实 SVG 圆环描边和文字显现，约 1.05 秒收束到自然音选中状态。静音占位不自动播放声音。
- 控制入口：进入演奏、重播、退出、正常/慢速。动画中禁止演奏触摸，允许退出；快速重播会取消旧动画任务。
- 浏览器核验：入口、动画中间帧、最终帧，交互与键盘操作，小窗口布局、减少动态效果、控制台错误。
- 交付可点击的本地 HTML 和浏览器预览，不把原型当作已完成的 Android 页面。

## 2. Android 导航与页面壳

修改 `ui/navigation/Routes.kt`、`AppNavHost.kt`、`ui/components/FloatingNavBar.kt`、`ui/home/HomeScreen.kt`；新增 `ui/practice/PracticeScreen.kt`。

- 添加 PRACTICE 路由及第五个导航项，统一导航顺序，移除相关四页下标假设。
- 入口页复用现有主题、卡片、标题和主动作按钮，提供进入演奏与现有悬浮窗入口。
- 完成普通页返回/滑动行为后再引入全屏舞台，避免把方向处理散落到所有页面。

验收：入口可达、导航标签不挤压、首页侧栏同步、其他页面状态保留。

## 3. 纯逻辑按键状态与音高映射

新增 `ui/practice/PracticeSession.kt` 及对应单元测试。

- 输入为音符按下/释放、调式切换、半音切换、取消全部触摸；输出为当前视觉状态与 note-on/note-off。
- 单音后按优先，按触点 ID 释放，旧触点释放不误停新音，不自动恢复旧触点。
- 模式影响后续 note-on；自然音初始状态固定，重入清空触点。
- 测试 8 键×3 调式×2 半音映射，涵盖 MIDI 48、85 两个边界与采样文件对应关系。

## 4. 同源布局与实时开场

新增 `ui/practice/PracticeStage.kt`、`PracticeKeyboard.kt`；必要时将几何函数放到同目录的小文件。

- 将经 HTML 确认的参考坐标和时序迁移到 Compose Canvas/布局动画。
- 单份几何同时用于绘制与命中检测，圆形整体等比缩放；按钮状态、高音点、半音标记与 session 一致。
- 在进入前记录方向策略、系统栏与屏幕常亮状态；先请求横屏并确认可用尺寸，再运行动画。
- 状态明确分为等待方向、开场、演奏、退出；可取消、不可重入。系统无法提供足够横屏区域时回到普通页，不盲目进入。
- 减少动态效果时用短淡入；音效仅保留可注入的可选入口，默认空实现。

验收：不同长宽比仍保持圆形与相对间距；动画中退出、转屏、切后台都能恢复系统状态。

## 5. 样本准备与本地发声

新增 `audio/HarmonicaSampler.kt`、采样索引与必要的离线准备脚本；资源放入应用 assets 的独立 harmonica 目录。

- 沿用现有 WAV，校验实际音高、去头部静音、覆盖完整 MIDI 48–85 音域。仅打包所需文件。
- 离线为每个样本生成经试听的稳定循环区间，保留原始音头，续音采用短交叉淡化；不将整段采样直接循环。
- 使用可控 PCM 流式输出（AudioTrack），后台预加载/准备，短缓冲、note-on 起音、note-off 淡出。避免每次按键重新读文件或新建音频输出对象。
- 调用边界使用小接口与 session 分离；音频焦点丢失、触摸取消、生命周期退出统一 all-notes-off。
- 明确加载状态与失败重试，不在音源未准备好时展示可演奏状态。

验收：短按及时响应；长按 15 秒以上不重启音头、无接缝点击声；快速切键和松手收音正常；音源离线可用。缓冲参数以目标设备实测调整，不承诺未经测量的延迟数值。

## 6. 悬浮窗端到端演练

- 保留现有服务的截图、定位与手势流程；舞台接收真实 MotionEvent，不增加内部自动播放器。
- 开场期间不允许开始有效演奏；布局稳定后才向用户呈现可演奏状态。必要的服务协调仅传递准备状态，不传入预设坐标绕过定位。
- 核对自动点调式、半音、长按音符、暂停/恢复和切歌；演练场离开时停止当前演练触摸和音频，防止手势继续落到其他 App 页面。
- 日志区分文字/边框定位、触摸和音符事件，诊断复用现有导出功能。

## 实施约束

- KISS/YAGNI：首版只实现已确认的演练闭环，入场音效保持明确的待用户素材状态。
- DRY：几何、按键状态、采样映射只有一份来源，手动与自动触摸共用。
- 单一职责：导航、动画/触摸、纯状态逻辑、音频输出分开；不继续扩大已有无障碍服务的职责。
- 所有文本文件 UTF-8 无 BOM；不提交私人诊断截图、密钥或与本功能无关的工作区改动。

## 本轮落实与验证（2026-09-27）

- 演练场入口收敛到「我的」启动按钮下方；取消独立导航页和侧栏入口，沿用现有 ActionPill，旁边提供紧凑的背景导入菜单。
- 根据完整 2388×1080 游戏截图，参考裁切有效宽度取 1970，琴键区约占屏宽 70%，以屏高 53% 为中心；与原 HTML 的 92%–96% 占比相比缩小。圆形始终等比，参考半径与键距不变。
- 舞台采用独立 `PracticeActivity` + 原生 `PracticeKeyboard` Canvas。独立窗口拥有横屏/隐藏系统栏/常亮，返回恢复主窗口；普通入口仍是 Compose。这样无需修改主 Activity 的方向策略，也不把飘雪带入截图。
- Canvas 绘制和 MotionEvent 命中共用 `PracticeGeometry`。半音和调式在 ACTION_DOWN 直接更新，无点击松手等待、动画或防抖；# 为数字字号的一半并置于左上，升降调立即更新高低音点。按住的旧音保持原音高，下一次 note-on 使用新模式。
- 音源离线准备脚本：`tools/prepare_harmonica.py`。38 个文件覆盖 MIDI 48–85，保留原音头，在 2–4 秒持续音区域选取相似波形接缝，32ms 重叠淡化。为减少包体只保留到循环末端，不打包每个 WAV 后续重复持续音；总资源约 12MB。
- 音频使用单个低延迟 AudioTrack 和 5ms 处理块；短淡出、换音交叉淡化，音频焦点中断、取消触摸、退出与切后台统一收音。实际设备延迟未测量。
- 服务仅新增开场就绪检查，识别坐标仍由截图产生。Android 11 以下不能截图，演练场自动播放会提示版本要求；手动弹奏不受此限制。
- JVM 测试覆盖 48 种映射组合、交错抬指、绘制/命中几何，以及每个音源 20 秒 PCM 续音后收音。
- 模拟器 instrumentation 已验证六种调式/半音画面的截图识别、DOWN 立即切换、音符触摸、退出及加载/动画中途退出。截图由实际 Android View 绘制，不是 HTML 代替。
- 尚未覆盖：手机扬声器/耳机上的延迟与接缝听感、用户设备上悬浮窗完整一首曲目的端到端播放。模拟器测试未授予无障碍权限、未绕过服务识别向播放器传坐标。
- 入场音效保持静音，待用户提供素材后单独接入；没有合成替代音效。

复验：`./gradlew.bat testDebugUnitTest assembleDebug assembleDebugAndroidTest --offline`。
安装主 APK 与 androidTest APK 后运行：`adb shell am instrument -w app.luoxianlv.debug.test/app.luoxianlv.PracticeInstrumentation`。

最终检查：73 项 JVM 测试，71 通过、2 跳过、0 失败；Debug APK 构建通过。全量 lintDebug 报 10 个既有错误（旧截图方法 API 注解、styles API 标注、local.properties、AnalyticsDebugScreen、AppNavHost 的 Activity 转型及 UpdateManager BOM 字符）；新增演练场模块无 lint 错误。没有设置忽略基线掩盖这些错误。

## 原始 Wallpaper Engine 项目接入（2026-09-27 追加）

- 保留原始文件：通过系统文件选择器导入 scene 项目文件夹或 ZIP；复制到私有 UUID 目录，完成校验后才切换选择。无转换、无预渲染导出。详细兼容范围与依赖见 `docs/third-party/wallpaper.md`。
- 背景使用隔离、禁外网的 WebView/WebGL；键盘与音频继续原生实现，共用原有几何与状态。默认背景为横屏动漫夕阳插画，键盘区域渐变压暗，使明亮背景下也能区分模式。
- 移除 root 的 cutout padding；横屏窗口允许绘制进刘海区域，背景铺满，仅退出按钮避让安全区。根窗口和加载底色改深色，避免无导航栏设备露出浅色条。
- 38 个采样保留首次弱起音头，长按仅循环持续段。新增 sentinel 测试：循环 12000 帧不重新经过静音音头；现有 38 音、20 秒续音与收音测试保留。
- 原始黑洞样本的 ZIP 导入、路径越界拒绝、失败保留选择、实时画面变化、完整窗口六种模式截图识别和触摸均纳入 instrumentation；截图改为 PixelCopy，包含真实背景与原生控件。
- KISS/YAGNI：只开放本轮可验证的 scene 导入，不扩展网页或应用壁纸；DRY/SOLID：导入存储、背景渲染和按钮 UI 各自独立，复用原有键盘与音频。
- Android 硬件模拟器的宿主图形后端曾异常退出；使用 SwiftShader 模拟器完成复验。手机 GPU 性能、长时间温度耗电以及所有其他工坊场景尚需实机确认。

本轮最终验证：75 项 JVM 测试，73 通过、2 跳过、0 失败。原始黑洞的 ZIP 导入、拒绝越界并保留旧选择、实时帧变化与六种模式回归通过；默认背景（手势导航、启用 tall cutout 模拟）六种模式与退出回归通过。退出状态由 `finish()` 立即关闭，避免等待窗口动画。Debug APK 为约 35.8 MB，DEX 检查没有 Umeng/EFS 类，未内置用户工坊项目。依赖、兼容范围和本地补丁在 `docs/third-party/wallpaper.md`。

## 时变默认背景 Debug 版（3113554287）

- 根据用户新要求，在 Debug assets 内置原始伊蕾娜项目，APK 约 117 MB；此前 35.8 MB 为未内置素材的版本。只迁移默认选择一次，后续用户导入保持有效。
- 原项目四时段逻辑不改写。通过脚本沙箱统一提供真实本地时间或指定 HH:mm；复用同一时间提供器满足场景切换与时钟文字（DRY），与动画时钟、原生音频分离（SOLID）。菜单只提供跟随/指定两个选项（KISS/YAGNI）。
- 手机视频资源管理单独实现：隐藏时段释放解码器，重新显示恢复位置；首次加载用原预览图，视频首帧就绪后淡入。WebView 保留极低非零 alpha 以防其合成器停止而无法完成首帧。
- 实测挑战：模拟器四路 4K 解码资源重、纹理就绪晚于媒体播放状态，因此回归等待真实彩色帧，不以播放状态冒充出画面；当前低性能设备首次加载仍可能较慢。
- 最终 Android instrumentation 通过：内置默认加载；08:00、12:00、18:00、22:00 四套实际画面；固定时间下视频继续变化；原始 ZIP 导入；立即退出。截图使用 PixelCopy。额外两个 JavaScript 时间测试通过；JVM 仍为 75 项，73 通过、2 跳过。
- APK 内 project.json、scene.pkg 与用户指定目录逐字节一致，Debug DEX 继续不含 Umeng/EFS。下一步为用户真机的首次加载速度及长期温度耗电验证。


### 系统 ZIP 导入（2026-09-27）

- 已加入“导入落弦律壁纸”系统文件打开/分享入口，处理临时授权 content URI；应用内入口复用同一导入流程。
- ZIP 支持外层文件夹、中文文件名、Windows 分隔符；scene/video/image/gif/web 按 project.json 分派渲染，原始文件不改写。
- WallpaperArchive 负责解包与路径约束，WallpaperProjectStore 负责项目验证与选择，WallpaperResources 负责只读资源和媒体范围请求；分离职责体现 SOLID，入口复用体现 DRY，保留单项目导入和离线播放体现 KISS/YAGNI。
- 难点是 Android 资源大小写、视频读取及网页宿主隔离；分别用受限路径查找、Range 响应及严格 iframe 沙箱处理。
- 新增 5 个归档单元测试；WallpaperImportInstrumentation 覆盖系统 VIEW/SEND、octet-stream、图片/视频/网页真实渲染、失败回滚和用户原始目录 ZIP。
- 交付后在真实 QQ 与目标手机验证选择器和复杂壁纸表现；不声称已验证全部 Wallpaper Engine 项目。


### 演练场工具栏和竖屏壁纸库（2026-09-27）
