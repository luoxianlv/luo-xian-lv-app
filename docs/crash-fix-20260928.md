# 1.0.7 前台服务启动超时修复

## 证据与范围

2026-09-28 通过用户已登录的 Edge 查看友盟过去 48 小时列表，并打开昨日样本与系统小窗异常详情。列表共 60 次错误，其中前台服务超时相关聚合项合计 49 次；这些是当前时间窗口的事件数，不是去重用户数。

- `11735339636046`：摘要虽为 `android.app.StackTrace`，完整异常仍是 `ForegroundServiceDidNotStartInTimeException`。昨日 Redmi K50 / Android 14 / 1.0.7 样本与今日 Android 15 样本均指向 `MainActivity.onResume → MusicAccessibilityService.showFloating → startForegroundService`。
- 其他前台服务聚合项指向同一个 `PlaybackForegroundService`，只是 Android 版本的异常类名不同。
- `removeFirst()` 错误在此窗口中来自 1.0.6，当前代码已使用兼容写法，不能据此断言 1.0.7 仍有该问题。
- `11735331021046`：红魔 NX809J / Android 16 / 1.0.7。实际异常为 `IllegalStateException: This activity is currently not freeform-enabled`，来自系统 `DecorCaptionView.toggleFreeformWindowingMode`，与播放服务超时无关。

没有证据证明所有历史闪退都属于同一原因；也未将录屏中的具体设备与某个友盟用户绑定。

## 修复

1. 每次 `onStartCommand` 首先调用 `startForeground`，再读取偏好与检查无障碍。旧代码只在 `onCreate` 登记，同一实例停止后又启动时会漏掉登记。
2. 播放服务集中管理正在启动、已进入前台和停止意图。首页反复恢复不会重复向系统发起启动；启动中的停止请求等前台登记后兑现，避免外部 `stopService` 与启动交错。
3. 关闭使用 `stopSelfResult(startId)`，只有停止的是最新启动命令时才撤掉前台通知；保留原有通知入口、停止按钮和粘性恢复行为。
4. 首页只拦截消息与系统堆栈同时匹配的小窗模式异常，记录中文警告并丢弃该次失效触摸。其他应用异常继续抛出，不做全局吞异常。
5. 崩溃同步写入独立 UTF-8 日志后仍交给原异常处理器；保留最近两份。诊断 ZIP 增加 Android 11 起的系统退出记录，区分 Java/Native 崩溃、ANR、低内存及主动退出。

服务启停仍在主线程串行执行，不引入常驻线程、延时重试或新的服务，保持职责集中。

## 验证

- Debug、Release 单元测试各 88 项：86 项通过，2 项可选环境相关测试跳过。
- Android 16 模拟器服务回归：20 次启动立即取消、100 次重复恢复、绑定保留同一服务实例后停止再启动、通知停止、交错开关，以及最后 12 秒超时观察，全部通过。
- 对照实验：仅临时恢复 HEAD 的两份服务源码，用相同测试运行，旧实现发生 `ForegroundServiceDidNotStartInTimeException` 并结束进程；随即恢复修复源码与安装包。绑定是测试中用于稳定保留同一服务实例的手段，生产代码未新增绑定。
- 同次旧实现崩溃被新的本地崩溃记录器捕获，确认进程退出前能落盘。
- Release 和精简 Debug 的 R8 构建通过，映射表确认前台登记保留在 `onStartCommand`；最终精简 Debug 已安装并完成冷启动。Release 产物未签名，未发布。
- 外部目录、旧壁纸迁移、UTF-8 日志、退出原因 JSON 和 FileProvider ZIP 分享读取通过设备验证。测试先等待 Application 启动迁移结束，避免自身与迁移线程争抢样本。
- 服务测试运行时须在测试进程启动后重新连接模拟器无障碍；Instrumentation 启动会终止旧应用进程。通知动作测试需要模拟器授予通知权限。

模拟器不能代表所有厂商系统；红魔小窗保护已做正反例单元测试，仍需该机型回归。Release 的 R8 构建与单元测试也不能替代正式签名包在真机上的验证。

全量 `lintRelease` 仍有此前已有的 API 标注、资源版本等错误；本次构建所需的 `lintVital` 通过，不将其等同于全量静态检查通过。

## 参考

- [Android Service 生命周期](https://developer.android.com/reference/android/app/Service)：重复启动会产生多条命令，`stopSelfResult` 按启动序号确认停止。

下一步用修复包在受影响手机上验证返回首页、切页和开关悬浮窗；若仍异常，诊断 ZIP 已包含原始堆栈与系统退出原因，可继续按真实证据定位。
