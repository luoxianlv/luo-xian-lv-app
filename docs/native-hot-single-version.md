# 单版本原生热更

热更目标采用唯一 `targetVersionCode`，不是展示用 `versionName`，也不是接口能力 `hostContract`。例如当前 1.0.10 的安装版本号为 17；对应热更不会投放到 16、18 或未报告安装版本的设备。

客户端从系统 PackageManager 读取实际安装版本；服务端检查候选、对象下载许可、激活许可，客户端在下载前、授权前、热更加载及稳定版本冷启动时再检查。签名包含目标版本号，不能只修改标签或 HTTP 请求把另一个版本的包改成适用。

CLI 创建配置须指定 `init --target-version-code 17`；`pack` 拒绝遗漏或 0。`verify --app-version-code 17` 可核对本次安装版本。业务、资源及增量包使用同一目标清单；发布和回退包必须属于同一版本。APK 升级后，不加载只针对旧安装版本的缓存代码；用户谱子、壁纸和设置沿用原有存储。

为读取历史签名与已登记恢复包，旧清单没有目标字段时继续按原兼容规则解析；当前 CLI 不再新建这种通用包。宿主接口、编译 SDK、运行时 ABI、数据格式、签名、灰度和健康门禁仍然独立生效。

Debug 线上验收使用 `app.luoxianlv.debug / test`，即使 API、数据库和 OSS 与生产共用，也不会投放给正式包。验收工具必须显式传 `-TestOrigin https://www.luoxianlv.cn`，计划与安装配置的源站必须一致；默认仍走回环本机。正式 APK 不能运行此验收。

本轮之前的正式签名候选未包含新增的单版本客户端代码；正式发包前必须从当前源码重新生成，不能直接发布旧候选。本轮 Debug 的完整链路证据不能代替正式签名包的同等在线验收。
