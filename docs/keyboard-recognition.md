# 按键文字与圆环联合定位回归（2026-09-27）

原算法要求至少 7 个音符数字及全部 4 个调式标签。调式文字受背景干扰或悬浮窗遮挡时，即使音符行完整，也会返回定位失败。

本次在灰度、局部对比度和连通域识别上增加圆环拟合，不新增运行依赖：

- 用至少 5 个同高度、同行的数字匹配八键等距网格，允许补全 3 个缺失数字；候选间距也允许从不相邻数字计算。
- 缺失边缘数字时，需要调式行校验序号，避免整行偏移一个或多个按键；只有一个边缘数字缺失时，保留原有邻近升号校验。
- 先尝试完整调式行识别，失败后用至少 2 个位置、行高和横向残差一致的标签校正几何模板，补全其余调式位置。
- 常规文字路径失败后，允许仅 3 个数字提出多个布局候选；至少 6 个音符边框与 3 个调式边框一致时才接受补全。候选按边框支持数量择优。
- `ButtonBorderDetector` 计算 Sobel 梯度，沿圆周 48 个方向采样。分粗搜索和逐像素精修，要求多个扇区支持同一边缘方向，结合圆弧覆盖率评分，避免局部亮墙线或复杂纹理冒充圆环。
- 分别拟合音符行、调式行的平移与缩放。用圆心、半径及行内位置残差剔除异常候选，再补全缺失位置；调式状态检测也使用实测半径。完整文字识别在弱边框场景仍可使用。
- 推算位置与实际观察分开记录。只有文字或边框提供直接证据的调式按钮才参与状态确认。
- 日志记录 `observedNotes=n/8 observedModes=n/4 noteBorders=n/8 modeBorders=n/4`，分别表示文字与边框证据数量。
- 截图转换和识别移入单线程后台任务；主线程只应用结果。保留 generation 与屏幕状态检查，暂停、退出或旋转后的过期结果不影响演奏，截图缓冲与位图在 finally 中释放。

表中“修改前”指最初的 7 数字/4 标签算法；上一版局部文字补全也已达到 42/42。本轮进一步验证文字缺失、比例变化时的恢复能力，未据此推算真实设备总体成功率。

回归检查音符坐标、行高度和当前升调/自然音状态，不只检查返回值非空。新增测试覆盖：

- 去背景参考图以及两张真实游戏截图，各擦除 5 个数字、保留边框，测试两种剩余数字分布；6 个变体均正确补全。
- 擦除全部 4 个调式标签，仅靠圆环定位。
- 调式行单独缩放到 85% / 113% 并移动，验证其位置不被音符行固定比例绑死。
- 整个键盘缩放到 76% 并改变屏幕留白，验证按键序号及坐标。
- 无琴键、竖屏、直线背景、证据不足，以及上一版局部缺失测试。

`keyboard-reference.gray` 来自用户提供的按键图片，格式与已有 `.gray` 样本相同：小端宽高各 4 字节，随后每像素一个灰度字节。私人游戏截图仅存工作区 `tmp/keyboard-debug/`，不加入 App 仓库。

在 App 仓库目录运行：

```powershell
./gradlew.bat testDebugUnitTest assembleDebug --offline
```

## 后续实机验证

安装调试包，重点复测室内墙面、室外亮背景、升调状态以及悬浮窗靠近调式行的场景。当前结果是截图回归，不代表已经验证实机点击与演奏。

算法能推算被遮挡按键的位置，但不能让手势穿透覆盖在上面的系统弹窗；演奏前仍需关闭系统弹窗。稀疏文字路径仍需要至少 3 个数字及足够的两排边框证据，不支持完全无文字、无边框时盲目演奏。
